# Repo Facts

- `ruff check apps` is clean as of 2026-05-17, and `get_errors` on `apps/` reported no LSP diagnostics after the cross-app typing refactor.
- Calendar unified summary now returns unpaginated summary-only `general_events` and `tasks`, enforces a maximum inclusive 31-day window, and uses `CalendarSummaryService` plus `collapse_for_range()` so recurring parents appear once per window instead of expanding every occurrence. Full per-day detail moved to `GET /api/v1/calendar/day?date=YYYY-MM-DD` via `CalendarDayService`. This contract is covered by `tests/playwright/tests/calendar/calendar.spec.ts` and passed on 2026-05-17.
- Core auth now exposes typed auth results in `apps/core/services/auth_service.py`: `TokenPair` and `AuthenticatedUserTokens`. Login token issuance routes through `AuthService.issue_tokens()`, and user lookup returns `UserLookupResult` from `apps/core/services/user_lookup_service.py`.
- Assistant direct responses now use `LLMResponsePayload` in `apps/assistant/services/llm_service.py`, and thread module settings are normalized through `ThreadModuleSettingsData` in `apps/assistant/serializers/thread_settings.py` before specialization and query-adapter logic consumes them.
- Calendar recurrence and mutation updates now flow through `CalendarMutationInput` in `apps/calendar/services/mutation_input.py` and `RecurrenceRuleData` in `apps/calendar/utils.py`, which removes in-place mutation of raw `validated_data` across recurrence scopes.
- Docusafe grant/revoke and temporary-share access now use typed request/result seams in `apps/docusafe/services/access_service.py`, `apps/docusafe/services/share_owner_service.py`, and `apps/docusafe/services/share_public_access_service.py`.
- Feed module (`apps/feed`) uses `Feed.creator` FK for post authorship (audit `created_by` CharField preserved), JSON-array access control aligned with calendar filtering but stricter `all` validation, write serializers for mutations, `GlobalAPIMessageCodes` error envelopes, and Playwright coverage in `tests/playwright/tests/feed/feed.spec.ts`. Legacy `family_feed*` tables from core are orphaned in state-only migration `core.0009`; new tables are `feeds`, `feed_comments`, `feed_reactions`, `feed_shares`.
