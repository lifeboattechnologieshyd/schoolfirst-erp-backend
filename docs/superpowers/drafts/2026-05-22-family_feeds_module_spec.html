What is Family Feeds?

A private social timeline exclusively for family members. Users can post rich media — text, images, videos, YouTube links, and web links — and control visibility at a granular level. Think of it as a walled-garden Instagram where the walls are family trees and close groups.

Access Model

only_meAll three access arrays are empty. Creator ID alone determines visibility. Useful for drafts or very private memories.
allFrontend sends the one family ID and every close-group ID the user belongs to. All family members across groups see the post.
mixedUser hand-picks a combination: one or more family IDs, close-group IDs, and/or individual user IDs. Arrays carry only the selected entities.

Feed Types

1Texttext

A single string body. No media attachments.

2Imageimage

One image URL + optional caption text.

3Videovideo

Uploaded video URL + optional caption text.

4YouTubeyoutube

YouTube URL (for native embed) + optional caption.

5Linklink

External URL + optional caption text. Opens in browser.

Business Rules

RuleDetail
Post deletionCreator can delete their own post. No editing allowed.
Comment deletionPost creator can delete any comment on their post. Commenter can delete their own comment.
No nested repliesComments are flat — no parent_comment_id concept.
Feed orderingAlways chronological (newest first) for now.
Creator is implicit viewerNo need to add creator ID to access arrays; access is always granted to creator.

Feeds Endpoints

POST
/api/v1/family-feeds/
Create a new feed post. Access arrays populated by frontend based on access_type selection.
GET
/api/v1/family-feeds/
Fetch feed list. Chronological (newest first). Supports filters + search.
?creator_id= ?feed_type= ?access_type= ?search= ?page= ?page_size= ?from_date= ?to_date=
GET
/api/v1/family-feeds/{feed_id}/
Fetch a single feed post by ID.
DEL
/api/v1/family-feeds/{feed_id}/
Soft-delete a feed post. Only creator can delete. Sets is_deleted=true and deleted_at.

Comments Endpoints

POST
/api/v1/family-feeds/{feed_id}/comments/
Add a comment to a feed post.
GET
/api/v1/family-feeds/{feed_id}/comments/
Fetch all comments for a post. Returns in chronological order (oldest first). Supports ?page= ?page_size=
DEL
/api/v1/family-feeds/{feed_id}/comments/{comment_id}/
Delete a comment. Allowed if: requester = commenter OR requester = feed creator.

Filter & Search Notes

search= performs a case-insensitive ILIKE on body_text. Future: extend to full-text search index.
creator_id= filters to posts by that specific user — useful for "My Posts" view.
feed_type= accepts comma-separated values: ?feed_type=image,video
from_date / to_date filter on posted_at (ISO 8601 format).

AI Tool Calling — Chatbot Integration

These tool definitions allow the in-app chatbot to post feeds and comments on behalf of the user through natural language. The AI never crafts raw API calls directly — it calls structured tools and the app layer handles auth and submission.

Tool: create_feed_post

// Tool definition sent to the LLM
{
  "name": "create_feed_post",
  "description": "Create a family feed post on behalf of the user. Use this when the user wants to share text, an image, video, YouTube link, or web link with family members. Always confirm access_type with the user if not specified.",
  "input_schema": {
    "type": "object",
    "properties": {
      "feed_type": {
        "type": "string",
        "enum": ["text", "image", "video", "youtube", "link"],
        "description": "Type of feed post to create"
      },
      "body_text": {
        "type": "string",
        "description": "Caption or full text of the post. Required for feed_type=text."
      },
      "media_url": {
        "type": "string",
        "description": "URL of image, video, YouTube video, or web link. Required for non-text feed types."
      },
      "access_type": {
        "type": "string",
        "enum": ["only_me", "all", "mixed"],
        "description": "Who can see this post. 'all' shares with all family and groups. 'mixed' allows specific selection."
      },
      "access_family_ids": {
        "type": "array", "items": {"type": "string"},
        "description": "Family IDs to include. Empty for only_me."
      },
      "access_close_group_ids": {
        "type": "array", "items": {"type": "string"},
        "description": "Close group IDs to include."
      },
      "access_user_ids": {
        "type": "array", "items": {"type": "string"},
        "description": "Individual user IDs to include in mixed access."

    },

}

Example AI conversation flow

User prompt → AI reasoning → Tool call
User: "Post a message for the whole family saying happy Diwali from us!"
AI resolves: feed_type=text, access_type=all, populates family + group IDs from user context, body_text="Happy Diwali from us! 🪔"
Calls: create_feed_post → confirms → app posts to API
Security note: AI never receives raw auth tokens. The app layer appends creator_id and auth headers server-side. AI only sends content and access intent.
